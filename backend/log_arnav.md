## 15. Face Recognition Crash Fix (`SystemExit` Escaping Its Handler)
- **Files Touched:** `app/osint/image_analysis.py`
- **What Changed:** Widened the guard around the `face_recognition` import from `except ImportError` to `except (ImportError, SystemExit)`.
- **Why:** When its model weights are missing, `face_recognition` calls `quit()` at import time. That raises `SystemExit`, which inherits from `BaseException` — so it slipped past *both* the `except ImportError` and the broader `except Exception` beneath it. Instead of degrading to `faces_detected: 0` as the fallback intended, any image uploaded to the OSINT toolkit would tear down the worker process. Reproduced by forcing the import to raise `SystemExit`; the analysis now completes and returns a zero face count.

## 25. Security Review Findings
- **Files Touched:** N/A (review phase)
- **What Changed:** Nothing yet — enumerating what the sweep found, ranked by exploitability against this deployment.
- **Why:** **Critical —** no authentication of any kind on any endpoint; the only `Depends()` in the codebase was `get_session`, which injects a database session, not an identity. The entire pre-existing surface — 58 operations across 53 paths — was reachable by anyone who could route to port 8000: `GET /api/faces/suspects` returned the entire criminal registry (names, aliases, FIR numbers, charges, convictions, jurisdiction, last known location, analyst notes, mugshots), `POST /api/admin/purge?days=1` mass-deleted stored evidence, `GET /api/admin/export/posts.csv?hours=2160` bulk-exported 90 days of monitored content, and `ws://…/ws/live` streamed live threat alerts. `PyJWT` and `PyOTP` were present in the environment but arrive transitively via `twilio`/`twikit` — nothing in `app/` imported them, so there was no partial implementation to finish. Compounding it, `main.py` set `allow_origins=["*"]` with `allow_credentials=True`, so any site an officer visited could drive the API as them.
  **High —** SSRF in `/investigate/url`, `/investigate/image-from-url` and `/investigate/post-media/{id}`: no host validation, redirects followed to a depth of 8, status codes and exception type names returned to the caller, making it a usable internal port scanner reachable from a pasted link. Biometric templates and mugshots stored as plaintext JSON in `sentinel.db`. Audit log with no actor and no write protection.
  **Medium —** no rate limiting anywhere; `/investigate/audio` read uploads with an uncapped `await file.read()` (the image endpoints correctly capped at 25 MB, audio did not) then wrote to disk and ran Whisper over it; `post_media.py` sliced `r.content[:_MAX_BYTES]` *after* httpx had already buffered the whole body, so the cap bounded nothing; `javascript:` URIs from crawled posts and RSS items reaching `<a href>` unvalidated (React escapes text but does not sanitise hrefs); post-derived text interpolated into an LLM prompt with a raw f-string at `groq_verifier.py:238`.
  **Confirmed sound —** no SQL injection (everything goes through the SQLModel expression API; the only `exec_driver_sql` is DDL over a hardcoded constant list); no `dangerouslySetInnerHTML` anywhere; every `target="_blank"` already carried `rel="noreferrer"`; `subprocess` calls use fixed argument lists with no `shell=True`; report download reads `pdf_path` from the database, not from user input; `username_lookup.py` validates the handle and probes a fixed site allowlist. Secret hygiene was already correct — `.gitignore` covers `backend/.env`, `x_cookies.json`, `*.session` and `sentinel.db`, and no credential file appears anywhere in git history.

## 26. Authentication and Role-Based Authorization
- **Files Touched:** `app/security/` (new: `roles.py`, `passwords.py`, `tokens.py`, `context.py`, `deps.py`, `bootstrap.py`), `app/routers/auth.py` (new), `app/models/models.py`, `app/main.py`, `app/config.py`, `requirements.txt`
- **What Changed:** Added a `User` table, scrypt password hashing, JWT sessions and three ranks — analyst, supervisor, admin — compared as "at least this rank" rather than by exact match. Guards are attached as **router-level** dependencies in `main.py`, not per endpoint. Destructive routes are elevated individually: registry deletion, photo unenrolment, watchlist deletion and alert escalation require supervisor; the whole `admin` router requires admin.
- **Why:** Router-level attachment is the load-bearing choice. Per-endpoint decorators mean a route added next month is public until someone remembers to annotate it — the failure mode is silent and the blast radius is a criminal record. With the dependency on the router, a new route is protected by default and has to be deliberately exempted. Confirmed by generating the OpenAPI schema: 68 operations across 61 paths, of which exactly two carry no security requirement (`POST /api/auth/login` and `GET /api/health`).
  Hashing uses `hashlib.scrypt` rather than bcrypt/passlib — memory-hard, in the standard library, so there is no extra wheel to audit or find broken after a Python upgrade. Hashes are self-describing (`scrypt$N$r$p$salt$hash`) so the work factor can be raised later and old hashes still verify, with `needs_rehash` upgrading them on next sign-in. `PyJWT` and `cryptography` were added to `requirements.txt` explicitly: both currently arrive transitively, and a dependency update that dropped them would break authentication rather than a side feature.
  `decode_access_token` pins `algorithms=["HS256"]`; accepting whatever the token's own header requests is the classic JWT break. `token_version` on the user row is the revocation lever — deactivating a user, changing their role or signing out bumps it, and every token already issued stops verifying on the next request instead of lingering until expiry. Verified end-to-end: after `POST /api/auth/logout`, the same token returns 401.
  First boot creates one administrator only when the user table is empty, generates a random password if `BOOTSTRAP_ADMIN_PASSWORD` is unset, prints it once, and sets `must_change_password`. There is deliberately no fixed default credential — the "admin/admin" that ships everywhere is the one that never gets changed.
  Login hardening: one generic error for every failure (a distinct "no such user" is a username enumeration oracle), a dummy scrypt verification when the username is unknown so response timing does not answer what the message refused to, and failure counting per account *and* per source address. Account-only lockout would let one attacker lock every officer out of their own system, so the IP limit absorbs a spray while the lockout stays scoped and self-clearing. Measured: 14 rapid bad logins produced `401×5 → 423 lockout → 429 rate-limit`.

## 27. Audit Log — Actor Attribution and Append-Only Enforcement
- **Files Touched:** `app/models/models.py`, `app/services/audit.py`, `app/database.py`, `app/services/scheduler.py`, `app/security/context.py`, `app/routers/auth.py`
- **What Changed:** Added `actor_id`, `actor_username`, `actor_role`, `actor_badge`, `ip` and `user_agent` to `AuditLog`, populated automatically from a request-scoped `ContextVar` set by the auth dependency. Added SQLite `BEFORE UPDATE`/`BEFORE DELETE` triggers on `auditlog` and `facesearchlog`. Added `log_action_strict` for operations where an unlogged action is worse than a failed one, and used it on biometric search, registry deletion and unenrolment. Exposed `GET /api/auth/audit` (admin only). Background ingest runs under a `SYSTEM` actor.
- **Why:** Attribution had to be impossible to forget. Threading an `actor` argument through every service call means some call site eventually omits it and writes an anonymous row — so the actor is read from context and every existing `log_action(session, action, target)` call gained attribution with no change at the call site. Actor fields are denormalised on purpose: username, role and badge are copied in at write time so the record still reads correctly after the account is renamed, demoted or deactivated.
  **This exposed a real bug during verification, worth recording.** The first implementation made `current_user` a *sync* dependency. FastAPI runs sync dependencies in a worker thread, and anyio copies the context *into* that thread but does not propagate writes back out — so the `ContextVar` set inside it was discarded, and the endpoint logged an anonymous actor. The audit table showed `login_success` correctly attributed (it passes the actor explicitly) while `password_changed` and `user_created` came back with `(none)`. Making `current_user` and the rank guards `async` fixed it: an async dependency runs in the request's own task, and the endpoint — sync or async — inherits a copy of that context. Re-verified: every row now carries `admin · admin · GJ-4471 · 127.0.0.1`.
  The triggers are database-level rather than application-level deliberately. An ORM rule protects nothing against a bug, a stray cascade, or anyone who opens the `.db` file — which is exactly the population a chain-of-custody log exists to protect against. Confirmed directly against the file with `sqlite3`: `UPDATE auditlog SET actor_username='someone_else'` and `DELETE FROM auditlog` both abort with `auditlog is append-only`, row count unchanged. Note during testing that a `BEFORE UPDATE` trigger fires per row, so an UPDATE against an empty table reports success while doing nothing — the first `facesearchlog` test looked like a miss for that reason and was re-run with a row present.
  Pre-existing audit rows keep empty actor fields. Backfilling a name onto actions taken before authentication existed would be fabricating evidence.
  `crawl_tick` sets and resets the `SYSTEM` actor around itself; the reset matters because `/admin/crawl-now` calls the same function from inside a request, and leaving the context stamped as `system` would misattribute the rest of that officer's request.

## 28. CORS Lockdown and WebSocket Handshake Gating
- **Files Touched:** `app/main.py`, `app/config.py`, `app/routers/ws.py`, `app/services/websocket_manager.py`, `frontend/src/services/ws.ts`
- **What Changed:** Replaced `allow_origins=["*"]` with a configurable explicit list, narrowed the allowed methods and headers, and made `config.py` raise at import if the list contains `*`. Added baseline security headers (`nosniff`, `DENY`, `no-referrer`, a `default-src 'none'` CSP, `no-store`). The WebSocket now checks `Origin` before `accept()` and requires an auth frame as the first message; `WSManager.connect` was split into `register`, so a socket joins the broadcast pool only after its token verifies.
- **Why:** `*` plus `allow_credentials=True` is rejected by browsers anyway, but the intent it encoded was the problem — combined with the missing authentication it meant any site an officer had open could drive the API from their session. Startup now refuses the configuration outright rather than letting it be reintroduced quietly.
  Browsers do not apply the same-origin policy to WebSockets and do not preflight them, so the CORS middleware never sees that handshake — cross-site WebSocket hijacking is a separate hole that a correct CORS config does nothing about. The token travels in the first frame rather than the query string because query strings land in access logs, proxy logs and browser history, and a session token in a log file is a session token in an incident report. Verified: no token closes with `1008`, `Origin: https://evil.example` fails the handshake outright, and a valid token on an allowed origin returns `{"type":"auth_ok"}`.
  A restrictive CSP costs nothing here because the API serves JSON and PDFs and never HTML.

## 29. SSRF Guard on the OSINT Fetchers
- **Files Touched:** `app/security/ssrf.py` (new), `app/osint/url_analysis.py`, `app/osint/post_media.py`
- **What Changed:** Added a blocked-range table (RFC1918, loopback, link-local including cloud metadata, CGNAT, multicast, reserved, IPv4-mapped IPv6, EC2 IMDS over v6), a scheme allowlist, and a `safe_chain` that walks redirects manually and revalidates **every hop**. `url_analysis` and `post_media` now route all outbound requests through it. A blocked resolution surfaces to the analyst as a high-severity finding rather than a silent failure.
- **Why:** These endpoints fetch URLs an analyst pastes, and those URLs come from the accounts under investigation — hostile by definition. On a police network the reachable internal surface is the sensitive one. Revalidating each hop is the part most implementations miss: a perfectly innocent public first URL redirecting to `169.254.169.254` defeats a check applied only to the initial input. Resolving all addresses for a name and rejecting the whole name if *any* is internal closes the DNS-rebinding variant; "use the good one" is not a property that survives a retry.
  Verified against a bypass list: `169.254.169.254`, `127.0.0.1:8099`, `localhost`, `10.0.0.5`, `192.168.1.1`, `[::1]`, `0.0.0.0`, `[::ffff:127.0.0.1]`, the decimal form `http://2130706433/`, `file://` and `gopher://` are all refused; `https://example.com` passes. Live through the API, a pasted metadata-service link now returns `blocked: true` and scores `dangerous`.
  Error text was narrowed to exception *type* names — the previous version could echo internal hostnames and addresses back to whoever supplied the URL.
  One implementation note: the first version returned an `httpx.Response` with `_content` monkey-patched to fake the byte cap. That was replaced with a plain `SafeResponse` dataclass, because a streamed response will not hand back `.content` once its context closes, and faking it through httpx internals would have broken on any library update.

## 30. Rate Limiting and Upload/Download Caps
- **Files Touched:** `app/security/ratelimit.py` (new), `app/main.py`, `app/routers/investigate.py`, `app/routers/faces.py`, `app/osint/post_media.py`, `app/config.py`
- **What Changed:** Added a sliding-window limiter with separate budgets — a default tier on every router, an expensive tier on face search, dossier expansion and all outbound-fetch/LLM endpoints, and a tighter unauthenticated budget on login. Capped audio uploads at 100 MB, read chunk-wise so an oversized body is rejected mid-stream. Remote media downloads now stream under a byte counter.
- **Why:** A sliding window rather than a fixed one, because a fixed window lets a caller spend the entire budget at 0:59 and again at 1:01. Keyed on the authenticated user where available, falling back to source address: keying on IP alone means one compromised account exhausts the budget for an entire district behind the same station NAT.
  Separate buckets matter — face search and Whisper transcription are orders of magnitude more expensive than a stats poll, and a shared budget would let ordinary dashboard polling starve the tools or vice versa. Measured: 24 calls against the 20/60s expensive budget gave exactly 20×200 then 4×429, while ordinary reads on the same token stayed at 200.
  The audio cap closes the cheapest denial-of-service in the system: an uncapped `await file.read()` followed by a disk write and a transformer pass. Chunked reading rejects the body mid-stream instead of allocating whatever the client chose to send. The streaming download cap fixes the same class of bug in `post_media`, where the existing `[:_MAX_BYTES]` slice ran after httpx had already buffered the full response — the constant looked like a limit and enforced nothing.
  Stated plainly in the module docstring: counters live in this process's memory. That is correct for the current single-instance deployment and for slowing brute force, but it is not distributed — two workers each enforce their own budget, and moving to gunicorn or Kubernetes means moving these counters to Redis.

## 31. Encryption at Rest for Biometric Data
- **Files Touched:** `app/security/crypto.py` (new), `app/osint/face_db.py`, `app/config.py`
- **What Changed:** Face vectors and mugshot thumbnails are sealed with Fernet before they touch the database. Reads go through `template_vector()`, which transparently handles both sealed (`vector_enc`) and legacy plaintext (`vector`) rows. `to_dict` now withholds the embedding in *both* forms. Startup refuses to run without a key when `SIMULATION_ENABLED` is false.
- **Why:** A leaked password is rotated in a minute; a leaked face vector identifies that person for life, and the registry it sits in marks them as a criminal suspect. That asymmetry justifies a dedicated layer rather than relying on filesystem permissions around `sentinel.db`. Fernet is authenticated (AES-128-CBC + HMAC-SHA256), so a tampered ciphertext fails loudly instead of decrypting to a subtly wrong vector that would quietly change who a search matches — verified: a mutated token raises rather than returning garbage.
  Backward compatibility is deliberate. Sealed values carry an `enc:v1:` marker and unmarked values are returned as-is, so enabling the key on an existing database needs no migration window and rows upgrade as they are re-enrolled. Verified: 128-float round-trip is exact, plaintext does not appear in the ciphertext, and both legacy and sealed template shapes read correctly.
  Scope is documented in the module: this protects the database at rest — a stolen laptop, a copied backup, a misconfigured share. It does not protect against an attacker with code execution on the running server, since the process must hold the key to work. Defence against that case is sections 26 and 27, not this.
  An undecryptable template is skipped and logged as an error rather than crashing the search — but it *is* logged, because a silently smaller registry means false negatives on identifications that nobody would otherwise notice.

- **Why:** Tokens go in `sessionStorage`, not `localStorage` — these are shared station terminals, and sessionStorage is scoped to the tab and gone when the browser closes, so an officer walking away does not leave a live session for whoever sits down next.

# 🛡️ SENTINEL

### Social Media Threat & Sentiment Analyzer

**Real-time OSINT threat intelligence for law-enforcement analysts** — monitoring
coordinated misinformation, communal-tension instigation, threats against
office-holders and organized cyberbullying across Facebook, Instagram, Reddit,
X and YouTube (all via official platform APIs), with first-class NLP for
**Gujarati, Hindi, Hinglish and code-mixed** content — the exact segment
generic moderation misses. Deployment scope: **Surat, Ahmedabad, Vadodara,
Rajkot** (configurable via `TARGET_CITIES`).

`git clone` → **one command** → live multilingual threat-intelligence dashboard.
**Zero API keys required.**

## ⚡ Quick start

### Option A — Docker (one command)

```bash
docker compose up --build
```

<sub>(Docker runs the lite NLP engine by default to keep the image small. To bake
the full transformer stack into the image, build with `INSTALL_ML=true docker compose up --build`.)</sub>

### Option B — no Docker (recommended for the full trained model)

```bash
# Windows
.\run.ps1

# Linux / macOS
./run.sh
```

These scripts do **everything** on first run: create the Python venv, install both
the base and the ML dependencies, install frontend packages, then start the backend
(**http://localhost:8000**) and frontend (**http://localhost:5173**) and open the browser.

Then open **http://localhost:5173** → *Enter Dashboard*. Within seconds you'll see:
a seeded 48-hour history, a live simulated multilingual stream flowing through real
NLP classification, alerts popping in over WebSocket, detected bot networks in the
network graph, and spike-detected trends. API docs live at http://localhost:8000/docs.

> **How is this possible with zero keys?** SENTINEL ships a *simulated ingestion
> mode* (the default): a labeled, template-driven generator producing realistic
> Gujarati/Hindi/Hinglish/English posts — including coordinated bot bursts — that
> flow through the **identical** pipeline real API data would. Add keys to `.env`
> and real platform adapters activate automatically alongside or instead of it.

## 🚀 Full setup guide (first clone → running app)

Follow this the first time you clone the repo. **You do not need any API keys** to
run the full app — the simulated stream drives everything. Keys are only for pulling
*real* posts (see [§ Going live](#-going-live-with-real-platform-apis)).

### Prerequisites

| Tool | Version | Check |
|---|---|---|
| Python | 3.11 or 3.12 | `python --version` |
| Node.js | 18+ | `node --version` |
| Git | any | `git --version` |
| (optional) Docker | any | `docker --version` |

### Step 1 — Clone

```bash
git clone <your-repo-url>
cd E-Rakshak-Sentiment-Analysis
```

### Step 2 — Start it

**The easy way** (installs everything, then runs):

```bash
# Windows
.\run.ps1
# Linux / macOS
./run.sh
```

**Or manually**, two terminals:

```bash
# ── Terminal 1: backend ──────────────────────────────────────────
cd backend
python -m venv .venv
# activate the venv:
.venv\Scripts\activate          # Windows PowerShell
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
pip install -r requirements-ml.txt   # the full transformer NLP stack (~2.5 GB)
uvicorn app.main:app --port 8000

# ── Terminal 2: frontend ─────────────────────────────────────────
cd frontend
npm install
npm run dev
```

### Step 3 — Get the trained model (see below)

Everything else regenerates itself, but the fine-tuned model does **not** ship in
git. Train it once (~10 min, one command) — details in the next section.

## 📦 What's NOT in git, and how to get it back

A fresh clone is **missing the files below** (they're in `.gitignore` — too big,
machine-specific, or secret). Here's exactly how each one comes back:

| Ignored path | What it is | How you get it | Automatic? |
|---|---|---|---|
| `backend/.venv/`, `frontend/node_modules/` | Installed dependencies | `pip install` / `npm install` (the run scripts do this) | ✅ auto |
| `backend/sentinel.db` | SQLite database | Created + seeded on first backend boot | ✅ auto |
| `backend/app/data/train.jsonl`, `test.jsonl` | Training/test datasets | Regenerated by `python -m app.ml.make_dataset` (the train step calls it) | ✅ auto |
| `backend/app/ml/eval_report.json`, `backend/reports/*.pdf` | Eval report, generated PDFs | Recreated whenever you run eval / generate a report | ✅ auto |
| **`backend/app/ml/models/`** | **The 913 MB fine-tuned MuRIL model** | **Retrain it (below) — does NOT come from git** | ❌ **manual** |
| `backend/.env` | Your config + API keys (secret) | Copy `backend/.env.example` → `backend/.env` (only needed for real keys or overriding defaults) | ⚠️ manual |

### Getting the trained model back

The app **runs without it** — full mode falls back to a slower zero-shot model, and
then to the lite lexicon engine, so nothing crashes. But to serve *the* fine-tuned
classifier (the 100%-accuracy MuRIL model), train it once:

```bash
cd backend
# make sure the ML stack is installed first:
pip install -r requirements-ml.txt

python -m app.ml.make_dataset     # builds train.jsonl + test.jsonl
python -m app.ml.train            # fine-tunes google/muril-base-cased (~10 min CPU)
python -m app.ml.evaluate         # optional: prints per-class P/R/F1
```

The model lands in `backend/app/ml/models/threat-classifier/` and is picked up
automatically on the next backend start (`NLP_MODE=full` is the default). Training is
reproducible, so every teammate who runs this gets the same model.

> **Alternatives to retraining:** if you'd rather share the exact model file, use
> [Git LFS](https://git-lfs.com/) to track `backend/app/ml/models/`, or zip that
> folder to a cloud drive and have teammates drop it back in. For a hackathon,
> retraining is the least error-prone option.

## 🔧 The `.env` file — full format

`backend/.env` is **optional**. With no `.env` at all, the app runs the full demo
(simulated ingestion + full transformer NLP + SQLite). Create one only to add real
API keys or change defaults:

```bash
cp backend/.env.example backend/.env   # then edit
```

Every setting, with its default:

```env
# ── Core ─────────────────────────────────────────────────────────────────────
# Database. Default = a local SQLite file. Swap for Postgres in production.
DATABASE_URL=                              # e.g. postgresql+psycopg://user:pass@host:5432/sentinel

# NLP engine: "full" (fine-tuned MuRIL + transformer sentiment/toxicity — the
# default) or "lite" (lexicon+heuristics fallback, zero downloads).
NLP_MODE=full

# Cities this instance monitors (drives watchlist geo-entries + text geo-tagging).
TARGET_CITIES=Surat,Ahmedabad,Vadodara,Rajkot

# Seconds between crawl ticks (drives the simulator/UI cadence).
INGEST_INTERVAL_SECONDS=4

# Politeness floor: never call the SAME live API more often than this many
# seconds, no matter how fast the tick runs. Protects you from being rate-
# limited/blocked. (YouTube is forced to ≥900 s because search is quota-heavy.)
CRAWL_MIN_INTERVAL_SECONDS=300

# Threat-score bands (0–100) for alerting.
ALERT_THRESHOLD=65
CRITICAL_THRESHOLD=74

# Keep the simulated stream on. Set to false once you have real keys and want
# ONLY live data (otherwise simulated posts mix in alongside real ones).
SIMULATION_ENABLED=true

# ── Reddit (official OAuth API — create a "script" app at reddit.com/prefs/apps)
REDDIT_CLIENT_ID=
REDDIT_CLIENT_SECRET=
REDDIT_USER_AGENT=sentinel-osint/1.0
# Seed subreddits, "subreddit:City" (City is an optional geo-tag):
REDDIT_SUBREDDITS=Surat:Surat,ahmedabad:Ahmedabad,Vadodara:Vadodara,rajkot:Rajkot,Gujarat

# ── Facebook Graph API ───────────────────────────────────────────────────────
# Reading pages you DON'T own requires Meta's "Page Public Content Access"
# (app review). FB_PAGE_IDS = seed pages, "handle_or_id:City" (City optional).
FB_ACCESS_TOKEN=
FB_API_VERSION=v21.0
FB_PAGE_IDS=

# ── Instagram Graph API ──────────────────────────────────────────────────────
# Needs "Instagram Public Content Access" review; seed accounts must be
# professional/business. IG_BUSINESS_ACCOUNT_ID = YOUR linked IG account's id.
IG_ACCESS_TOKEN=
IG_BUSINESS_ACCOUNT_ID=
IG_SEED_USERNAMES=

# ── X / Twitter API v2 ───────────────────────────────────────────────────────
X_BEARER_TOKEN=

# ── YouTube Data API v3 ──────────────────────────────────────────────────────
YOUTUBE_API_KEY=

# ── Generic Web/RSS (comma-separated feed URLs — local news outlets) ─────────
RSS_FEEDS=
```

**Format rules:**
- No quotes, no spaces around `=` (`KEY=value`).
- Leave a key blank/absent to keep its default; a live adapter simply stays
  **offline** until its keys are filled in.
- Comma-separated lists (`FB_PAGE_IDS`, `REDDIT_SUBREDDITS`, `IG_SEED_USERNAMES`)
  use an optional `:City` suffix per entry to geo-tag everything from that source;
  entries without it are geo-tagged from city mentions in the post text.
- **Never commit `backend/.env`** — it's gitignored on purpose (it holds secrets).

│ X API v2 · YouTube v3   │   │ toxicity + hate flags      │   │ report generation (PDF) │
│ generic Web/RSS         │   │ composite threat score     │   │ per-city geo-tagging    │
│  (APScheduler loop with │   │                            │   │                         │
│   per-API politeness    │   │                            │   │                         │
│   gaps — never hammered)│   │                            │   │                         │
└─────────────────────────┘   └────────────────────────────┘   └─────────────────────────┘
           ↓                              ↓                    ↓
        SQLite/Postgres (SQLModel)  →  FastAPI REST + WebSocket /ws/live

**Backend** `backend/app/`: `crawlers/` (adapter per platform), `ml/` (the NLP

`services/ws.ts` (reconnecting live socket), `pages/`, `components/`, `hooks/`, `data/`.

## 🧠 NLP pipeline

Two engines, one interface — chosen by `NLP_MODE` in `backend/.env`:

| | `full` (default) | `lite` (fallback) |
|---|---|---|
| Threat classification (4-way) | **fine-tuned google/muril-base-cased** (MuRIL — pretrained on 17 Indian languages incl. transliterated text; picked up from `ml/models/threat-classifier/` after a one-time `python -m app.ml.train`), else zero-shot **joeddav/xlm-roberta-large-xnli** | multilingual weighted lexicons + heuristic layer (mobilization, target-of-violence, misinformation framing) |
| Sentiment | **cardiffnlp/twitter-xlm-roberta-base-sentiment** | valence lexicons + emoji + threat-signal fusion |
| Toxicity / hate flags | **unitary/multilingual-toxic-xlm-roberta** | abuse lexicons + signal rules |
| Language ID + code-mixing | Unicode-script analysis + romanized marker wordlists (>97% on eval set) | same (shared) |
| Setup | `pip install -r requirements-ml.txt` (+ model downloads on first run) | zero downloads, <1 ms/post |

Both paths share normalization (URL/mention stripping, stretch-char collapse,
romanized-slang canonicalization: `nhi→nahi`, `jla do→jala do`), batched
inference, singleton model loading at startup, and graceful per-call fallback
from full → lite so the demo can never break — a machine without the
transformer stack silently serves lite instead of crashing.

**Labels** (exactly what the UI shows): `Incitement to Violence` · `Inflammatory` · `Fake News` · `Neutral`.

### Threat score (0–100)

```
score = 100 × ( 0.40 × severity(label) × confidence     ← classifier belief × class danger
              + 0.25 × toxicity                          ← hate/abuse intensity
              + 0.20 × virality                          ← log-scaled engagement + amplification bonus
              + 0.15 × keyword_severity )                ← strongest lexicon term matched

severity: Incitement 1.00 · Inflammatory 0.75 · Fake News 0.65 · Neutral 0.05
virality: min(1, log10(1 + likes + 3·shares + 2·comments + views/50) / 4)  (+0.15 if in a detected burst)
bands:    ≥74 → critical alert + auto-generated escalation packet · ≥65 → high alert · ≥50 → active threat
```

```bash
cd backend && python -m app.ml.evaluate
```

held-out test set (151 samples, disjoint slot vocabulary from training — no

|---|---|---|---|
| Incitement to Violence | 1.000 | 1.000 | 1.000 |
| Inflammatory | 1.000 | 1.000 | 1.000 |
| Fake News | 1.000 | 1.000 | 1.000 |

The dashboard additionally shows **live accuracy**: every simulated post carries

> *Honest caveat:* the built-in test set is generated from the same template

> HASOC-style code-mixed hate-speech data (`python -m app.ml.prepare_public_data
> --input hasoc_hi_train.tsv` — free registration at hasoc.github.io) and re-run
> training + evaluation.

## 🕸️ Network & campaign detection

Runs generically on any data (not just the simulator):

1. **Near-duplicate clustering** — word-3-gram Jaccard similarity + union-find
   over recent non-neutral posts catches copy-paste amplification.
2. **Cluster scoring** — synchronized posting windows, account age, follower
   counts, templated handle prefixes → a confidence score **plus human-readable
   "why flagged" evidence** shown in the UI (e.g. *"6 accounts posted
   near-identical text within 2m 55s · average account age 23 days · handles
   share a templated prefix"*).
3. **Graph** — networkx degree centrality sizes nodes (influence), average
   threat score colors them, bot-suspect accounts get dashed red rings.

Trends use sliding-window term velocity with **z-score spike detection** per
hashtag/keyword, language breakdown, and per-city threat heat for Gujarat.

## 🔑 Going live with real platform APIs

Every live adapter uses the platform's **official API** — no scraping, no
proxy tricks. Collection follows the **seed-source strategy**: instead of
crawling the open web, each platform monitors the top public sources for the
target cities (news pages, civic bodies, city subreddits), plus the analyst
watchlist. An optional `:City` suffix on any seed geo-tags everything it
produces; posts without a tag are geo-tagged from city mentions in the text
(English / Hindi / Gujarati spellings).

Copy `backend/.env.example` → `backend/.env`, add any of:

```env
# Facebook Graph API — seed pages per city (page id or username)
FB_ACCESS_TOKEN=...
FB_PAGE_IDS=tv9gujarati:Ahmedabad,SuratMunicipalCorporation:Surat,VMCVadodara:Vadodara

# Instagram Graph API — business discovery + watchlist hashtag search
IG_ACCESS_TOKEN=...
IG_BUSINESS_ACCOUNT_ID=...           # your linked IG professional account id
IG_SEED_USERNAMES=amdavadamc:Ahmedabad,suratsmartcity:Surat

# Reddit OAuth API (script app) — city subreddits + watchlist search
REDDIT_CLIENT_ID=...
REDDIT_CLIENT_SECRET=...
REDDIT_SUBREDDITS=Surat:Surat,ahmedabad:Ahmedabad,Vadodara:Vadodara,rajkot:Rajkot,Gujarat

X_BEARER_TOKEN=...        # X API v2 recent search
YOUTUBE_API_KEY=...       # YouTube Data API v3
RSS_FEEDS=https://example.com/feed.xml,...   # local news outlets
```

Restart — each configured adapter activates automatically and its posts flow
through the identical NLP → scoring → alerting → reporting pipeline. The
watchlist (editable in the UI) becomes the live crawl query. Set
`SIMULATION_ENABLED=false` to go fully live. Swap SQLite for Postgres with one
`DATABASE_URL`.

**API etiquette (important):** the scheduler enforces a per-platform
politeness gap — no live API is queried more often than
`CRAWL_MIN_INTERVAL_SECONDS` (default 300 s, YouTube 900 s because a search
costs 100 quota units), and adapters sleep ~1 s between the individual
queries inside one batch. Rapid-fire requests against a single endpoint look
like abuse and get the app/IP rate-limited or blocked — batch, then wait.

*Meta app notes:* reading Facebook pages you don't manage requires the
**Page Public Content Access** feature (app review); Instagram business
discovery and hashtag search require a linked **Instagram professional
account**, and Meta caps hashtag search at 30 unique hashtags per week (the
adapter queries only the first few watchlist hashtags per cycle and caches
hashtag ids).

## 📁 Dataset sources & content note

The bundled corpus (`backend/app/data/templates.py`) is **synthetic**, written
for this project across 4 languages × 4 categories, using deliberately generic
group references and fictional office-holders. It exists solely to train/demo a
*detection* system. External data supported: HASOC (Hindi/code-mixed
hate-speech, hasoc.github.io) via `app/ml/prepare_public_data.py`, which
documents the label mapping.
